### Phase 4a (Bred stats + Bloom) — COMPILES (the user built it, session 4); in-game results not reported yet
* **TESTED here (real JDK compile of the pure-Java package, 979,467 checks, 0 failures):** `Stat`, `Stats`, `Trends`, `Drift`, `Growth`, the new End
  allele `starborn` (Fertility id 4, in the End founder recipe at 40% per slot). The checks include every trend of the DESIGN table, zero-sum at quality 0
  for every ordinary allele, costs gone at quality 4, the starborn toll ignoring quality, unbiased rounding, the growth-time table, and a re-run of the
  simulation table in DESIGN "5. Bloom" (it matches the published numbers).
* **COMPILED by the user, not reported in-game:** the glue in `Bunnidog.java` (stats field + `Stats` NBT text tag, attributes =
  base x gene multiplier x stat multiplier, `growthTick()` in `tick()`, pups inherit stats in `getBreedOffspring`) and the stats read-out in
  `/bunnidogs genome` (BunnidogsCommands). The only new Minecraft API is `AgeableMob#getAge()` (see API_NOTES "Assumed in Phase 4a").
* How it plays now (numbers in DESIGN "4. Bred stats" / "5. Bloom"): every bunnidog has five stat points, all 0 at first (wild founders too). When two
  bunnidogs breed with carrots, each pup gets the parents' average plus a drift decided by the PARENTS' expressed genes (a stocky pair gains Vitality and
  loses Swiftness, +1/-1 per generation, zero-sum; wild and rare alleles are better). Quality is, for now, ONLY the starborn bonus (0.3 x sqrt(Bloom) per
  starborn parent, averaged), which raises gains and shrinks costs (later: guava tiers and Fortune add to it). Bloom makes pups grow up faster
  (x2 at 20 points, 60 s floor) or slower (down to 0.4x); starborn is the End-only Fertility allele (dominant, litters x0.7, and an unshrinkable toll
  of -1 Vitality and -1 Senses per generation).
* Stats are server-side only and have no visual cue yet; they show in `/bunnidogs genome` (points, attribute multiplier, minutes to adult, what the
  genes will push next generation, the starborn quality bonus). Set them for testing with
  `/summon bunnidogs:bunnidog ~ ~ ~ {Genome:"00-00-00-00-00-00",Stats:"50,0,0,0,0"}` or
  `/data merge entity @n[type=bunnidogs:bunnidog] {Stats:"0,0,0,0,100"}` (order: Vitality, Swiftness, Leap, Senses, Bloom).
  There is NO permission check on `/bunnidogs` (debug), so lock it before a public release.
* Cheat sheet: stocky pair (sturdy line) `00-00-00-11-00-00`; "Bloom build" (starborn + stocky + long ears) `11-00-00-11-00-44`; an End-like
  founder `00-aa-00-00-00-44` (void coat, starborn).

### Session 12 fix: infusing with a bred seed (user report: works with the creative-tab seed, not with a seed from breeding, always in survival, sometimes in creative)

* **Cause (found by reading, not reproduced; Claude cannot run the game):** a bred seed drops as a stack of ONE. `SeedItem.use` did `seedStack.shrink(1)` and then `inventory.add(bottle)`: with one seed the held slot becomes empty, it is the first free slot, so the bottle was placed into the very slot that vanilla clears right after `use` for an emptied stack. Names: `Player#setItemInHand(InteractionHand, ItemStack)` is new for the project (seen in NeoForge's tests, e.g. `BlockTests.java:86`); the rest is as before. Vanilla's `useItem` body is not in the NeoForge sources (patch context only), so how it treats a replaced hand stack is the open part.

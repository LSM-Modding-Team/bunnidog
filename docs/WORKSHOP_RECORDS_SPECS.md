# Physical workshop recipes

A resident can preserve a recipe it actually made in a paid, readable book.
Another capable beginner can attempt that recipe at the original Hearth after
its author is gone. The book supplies a procedure; only a committed paid operation
teaches personal Crafting. This extends the practical education in
[WORKSHOP_LEARNING_SPECS.md](WORKSHOP_LEARNING_SPECS.md), without inventing
inherited experience, a profession selector or a general recipe-search system.

## Actual examples and one real book

Only a successful native civic crafting transaction records a personal example.
It retains the exact recipe identity, original Hearth/owner/author, ordinary
ingredient item types/counts and actual result type/count from that transaction.
No material, custom result component or inventory is embedded as redeemable stock.
The current native recipe manager still determines every later payment/output.
Old familiar skills alone provide no example; an older expert must actually make
the recipe once before writing it. Personal examples survive whole-animal saves.

An independent craftsperson with independent Teaching capacity can walk to its
Hearth and write an example in an actual blank vanilla Book and Quill from the
common inventory. The existing native work period and one movement owner apply.
Food, care and useful production precede archival work. Writing grants no skill.
Existing journal pages are never overwritten; named covers and unrelated
components survive. One exact original slot transaction replaces one blank book,
even in a full inventory. Permission callbacks, original stock/authority,
redstone/locks and reentrant-operation guards are rechecked before commit.

The result is native readable **Workshop Notes / Notas de taller**, with a short
translated ingredient/output page taken from the actual example. There is no new
crafting recipe, setup screen, lecture timer or required guide chapter. A blank
book in the common store supplies the opportunity. Duplicate recipe records are
refused, and eight physical workshop records bound the archive, including opaque
future or malformed record items. Courier records retain their separate bound.

## Learn by doing after an expert leaves

An unoccupied registered adult beginner with Bloom +10 and independent Crafting
potential can use a live available record to attempt **that recipe**. The native
Society goal must still walk to the actual Hearth, perform the work period and
commit current exact inputs, result and remainders. Reading, opening the book,
watching a claim or merely possessing the item grants no experience or stock.
No prior Garden skill or personal Nest is required.

The book must remain in the original loaded common inventory, with the same
Hearth site and owner, through callback/commit checks. Removing the only
instruction source refuses payment and learning. A copied record in another Hearth provides no
authority, even with the same keeper. Supported minds still need an actual local
instructor; limited minds cannot bypass their inherited limits through a book.
Orders, other lessons, parcels, danger, rest and physical readiness still win.

The successful practical attempt uses the existing personal practice rule. Once
the animal actually knows independent Crafting it can keep working after the
book is removed. Neither its Gardening nor Building progress changes. A child
learning a resident-authored procedure retains the same later-independent-work
continuity requirement as other resident teaching; writing/reading alone cannot
complete the Hearth. An expert moving to another household must do a paid local
recipe there before authoring that household's own record.

## Bounded saved data

`craft_notes` is a bounded opaque string item component (4,096 characters). The
current version contains original UUIDs, one finite recipe ID, at most nine
ordinary ingredient units and one ordinary type/count result example. Native
item/component codecs preserve the physical written book. Unknown future records
remain unreadable exact items; they never upload skill or disappear on decoding.
Recipes are not recursively embedded in courier filters.

Personal `CraftProven` keeps at most thirty-two bounded example strings. Unknown
future example strings remain opaque through animal save/load and later paid
work. Missing old fields mean unproved, without erasing old skill. These examples
are individual experience, never genotype, offspring/seed or infusion content.
Reading caches are bounded and keyed by the actual registry access. No chunk
loading, remote inventory query, new skill schema or recipe execution script is
introduced. Personal learning remains l3; network **52** requires matching content.
